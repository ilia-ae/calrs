Двухфакторная аутентификация

Эта политика действует для локальных аккаунтов. При входе через SSO используется двухфакторная аутентификация поставщика удостоверений. Прежде чем менять политику, локальные администраторы должны настроить двухфакторную аутентификацию у себя. Если сделать её обязательной, локальные сеансы без второго фактора будут завершены, а при следующем входе её нужно будет настроить.

Jitsi (ссылки на встречи создаются автоматически)

Статус: выключено

Если в типе встречи выбрано место «Jitsi (комната создаётся автоматически)», calrs создаёт для каждой записи новую комнату: добавляет шаблон ниже к базовому адресу Jitsi. Обращаться к внешнему API не нужно.

Показывается гостям при выборе времени и в форме записи. Если не указано, показывается «Видеозвонок».
Доступные подстановки: {username} (организатор), {event} (короткий адрес типа встречи), {date} (ГГГГММДД), {random} (8 символов). По умолчанию: {event}-{random}. ⚠ Без {random} название комнаты предсказуемо: два гостя, записавшиеся на один тип встречи в один день, попадут в одну комнату и смогут видеть встречи друг друга. Постоянные комнаты допустимы (например, одна личная комната на организатора), но включайте этот режим, только если понимаете последствия.

Оставьте базовый адрес пустым, чтобы выключить автоматическое создание комнат Jitsi.

Вебхук для встреч (свой сервис видеосвязи)

Статус: выключено

Если для типа встречи выбрано место «Вебхук (свой сервис)», при подтверждении записи calrs отправляет её данные POST-запросом на этот адрес и ожидает в ответ JSON {"url": "https://..."}.

Показывается гостям вместо общей метки «Видеозвонок».
С HMAC calrs подписывает исходное тело запроса и передаёт подпись в заголовке X-Calrs-Signature: sha256=<hex>.

Оставьте адрес пустым, чтобы выключить вебхук для встреч.

Настройки SMTP

Статус: не настроено

Выбирайте Без шифрования, только если почтовый сервер работает на этой же машине и не поддерживает STARTTLS или использует самоподписанный сертификат. Письма и учётные данные передаются по сети открытым текстом.

Настройки можно задать и переменными окружения (они имеют приоритет над этой формой): CALRS_SMTP_HOST, CALRS_SMTP_PORT, CALRS_SMTP_TLS_MODE (starttls, tls или none), CALRS_SMTP_USERNAME, CALRS_SMTP_PASSWORD, CALRS_SMTP_FROM_EMAIL, CALRS_SMTP_FROM_NAME. Обязательны только CALRS_SMTP_HOST и CALRS_SMTP_FROM_EMAIL. Чтобы отправлять письма через локальный MTA без аутентификации, не указывайте имя пользователя и пароль.

Когда лимит исчерпан, calrs перестаёт отправлять SMS, но письма уходят как обычно, поэтому записи не сорвутся, даже если бюджет на SMS закончился.

Перед запуском: ограничьте страны назначения в настройках шлюза (в Twilio это Geo Permissions), используйте предоплаченный счёт без автопополнения и не выключайте капчу. Вместе эти три меры ограничивают, во сколько вам может обойтись атака с накруткой SMS-трафика.
